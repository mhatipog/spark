### A crucial semantic limitation was tested

A **physical or logical operator that preserves row order** does not imply the outer SQL statement **promises** that row order. For instance:

```sql
SELECT id
FROM (
  SELECT id FROM range(0, 12, 1, 4)
  ORDER BY id DESC
) AS x
```

The inner ORDER BY is not an outer ordering obligation: an outer SQL consumer can reorder rows. The automatic verifier must **return UNKNOWN**, not invent an external ORDER BY contract.

A separate positive control adds an explicit final `ORDER BY id ASC` to that exact outer query; the verifier **must extract** the outer ASC key and ignore the inner DESC when determining the required final ordering.

Both controls behaved as required in both official released engines, under AQE on/off. The resulting conservative extractor **does not traverse SubqueryAlias** on its way toward a purported top-level ordering obligation. It still permits directly exposed attribute aliases, LIMIT/OFFSET wrappers, and WithCTE where a true root Sort is established.

This is a **soundness guard** against converting an internal implementation detail into an output contract. It is neither a newly discovered Spark defect nor a novel sorting theorem.

### Why this is not yet a publishable research result

A separate earlier [automatic-obligations branch](https://github.com/mhatipog/spark/tree/research/queryproof-automatic-obligations-20261017/tools/queryproof_auto_obligations) already attained 60/60 key-extraction coverage and demonstrated a narrow Catalyst-derived top-k source witness. This branch is a **focused adversarial semantic extension**, not an independent achievement or a better general verifier.

The next meaningful milestone must use previously frozen **unseen correctness issues**, especially bag/null/subquery and aggregate errors that output ordering and membership witnesses inherently miss. Measure `FAIL / NO_VIOLATION_OBSERVED / UNKNOWN`, correctness sensitivity, false accusations and overhead against independently executed oracles. Do not silently promote UNKNOWN to PASS, or count repeated executions of one bug as independent coverage.

**Verdict:** Engineering validation: successful. Scientific novelty and journal submission readiness: low, pending blind cross-family evaluation and a genuinely new property-compilation method.
