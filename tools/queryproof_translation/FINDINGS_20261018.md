# QueryProof: Contextual translation certificates

**18 October 2026** — First implemented, independently checked finite-domain contextual translation validator and observation-guard synthesizer.

## Reproducible result

[GitHub Actions 39111884075](https://github.com/mhatipog/spark/actions/runs/39111884075): successful. The experiment constructs seven certificates, re-evaluates all of them using a separate Python implementation, and synthesizes the admissible semantic observation partitions for a known three-valued equality rewrite.

The frozen protocol at [FROZEN_PROTOCOL.json](FROZEN_PROTOCOL.json) was committed before the generator implementation.

| Evaluated context | Bounded equivalent? |
| --- | --- |
| Predicate as a bare positive filter | Yes |
| Predicate under NOT in a filter | No; concrete NULL witness |
| Predicate under IS NULL | No; concrete NULL witness |
| Predicate projected as a scalar Boolean value | No; concrete NULL witness |
| Predicate in positive AND filter with arbitrary 3VL sibling | Yes |
| Predicate in positive OR filter with arbitrary 3VL sibling | Yes |
| Predicate in a double-NOT filter | Yes |

The rewrite:

`(a=b) OR (a IS NULL AND b IS NULL) → (a IS NOT DISTINCT FROM b)`.

For a=0, b=NULL, the original expression yields NULL and the replacement yields FALSE. Thus the replacement is filter TRUE-set equivalent but *not* equivalent under NOT, IS NULL, or in a scalar value position.

The guard is **not** a hardcoded safe-context lookup. It enumerates the semantic image pairs of original/replacement over the equality/nullness abstraction D={NULL,0,1}, tests each of the five observational partitions over {TRUE,FALSE,NULL}, and permits precisely the partitions under which all pairs remain equivalent. It derives `ANY, TRUE_ONLY` as admissible and `FALSE_ONLY, NULL_ONLY, FULL_3VL` as inadmissible. Seven complete context certificates were independently checked against the exhaustive finite model.

## Strong limitations

This is *in-sample calibration*: the exact known historical Spark SPARK-58384 / DuckDB #23685 expression rewrite was supplied to the validator. Neither a Catalyst rewrite candidate nor its surrounding context is automatically recovered from the RuleExecutor trace **in this experiment**. It also does not yet generate and replay a failing Spark query from its standalone mathematical certificate.

The bounded model is complete only for this integer equality, NULLness and three-valued-context grammar, **not** general SQL equivalence. The separate checker is simpler and independently implemented, but shares the same intended SQL logic semantics and is not an external SMT/DBMS proof engine.

The program uses exhaustive finite evaluation, *not* Z3 or cvc5. The observation guard has no claim of original algebra or an independently discovered defect.

Earlier related work had achieved source-derived row-bag witnesses on B01/B02/B03 and an automatically selected causal rule-intervention pipeline with 3/3 historical restorations; all were in-sample. This experiment closes the specific next subtask: **verified counterexamples and strongest safe observation preconditions for a manually supplied known rewrite**. It does not complete full automatic optimizer translation validation or unseen-bug benchmarking.

## Next experiment

3. Produce a certificate naming the rule, expression, demanded observation, minimal input database and independently replayable outputs.
4. Evaluate on independent optimizer families not used in developing this implementation. Report unsupported, wrong, false accusations and overhead at the *issue-family* level. Compare fairly with actual database-testing/verifier baselines.
