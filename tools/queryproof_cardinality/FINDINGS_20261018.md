# QueryProof empty-input cardinality and three-valued scalar subquery

**Date: October 18, 2026. Status: two-version, in-sample correctness witness validated.**

The *same* original Spark optimizer rule RewritePredicateSubquery transformed historical wrong case B03 and correct control N03. Both analyzed InSubquery expressions required exact FULL_3VL observation. A Boolean observation lattice alone cannot distinguish them. The source global aggregate cardinality is the deciding extra dimension.

For any input bag R, the ungrouped global aggregation `COUNT(*)` produces exactly **one result row even if R is empty**. An uncorrelated scalar IN subquery should evaluate to a value v ∈ {TRUE, FALSE, NULL} independently of R. Rewriting it into a per-input-row flag and then `FIRST(flag)` breaks when R=∅: FIRST has no argument and produces NULL, while v could be TRUE or FALSE.

**Tested on unmodified official PySpark 4.0.1 and 4.2.0, both AQE modes:**
[GitHub Actions 39106990235](https://github.com/mhatipog/spark/actions/runs/39106990235). Both jobs succeeded.

The Python reference interpreter reads Spark's *analyzed Catalyst tree*: root global Aggregate with two outputs (COUNT of non-NULL constant and one uncorrelated scalar IN), source/inner direct Range operators (allowing only expression-ID-preserving SubqueryAlias/Project wrappers), safe lossless integer literal casts, and exact source Range start/end/step. It constructs count and IN membership independently without executing an equivalent optimized Spark SQL query or receiving expected output rows from the benchmark manifest.

Each variation was executed with AQE enabled and disabled on each release. Six deliberately unsupported shapes—grouped aggregation, filtered source, derived inner expression, non-Range input, missing subquery, and unsupported NULL-cast probe—were explicitly classified UNKNOWN. There were **no execution errors, and no unexpectedly accepted negative controls**.

The first experiments failed closed because the analyzed plan included an implicit INT→LONG Cast and an identity-only Project around a table-valued Range; the interpreter was deliberately expanded ONLY to these semantics-preserving constructions. These modifications were made after inspection and are **in-sample engineering development**.

### Elegant unifying semantic model

A proposed next abstract effect system is a product

`ObservationEffect = BooleanObservationPartition × SourceCardinalityObservation`.

For nullable SQL predicates, the first factor has Bell(3)=5 possible observational partitions of TRUE/FALSE/NULL. The second factor can begin with a ZERO versus NONZERO distinction for aggregate-empty behavior. More general bounded selection needs a cutpoint k: the saturating natural cardinality algebra `κ_k(n)=min(n,k+1)` preserves composition of addition and multiplication under saturation (subject to using cardinalities only where those operators actually model the relational operation). This is established finite abstract interpretation / semiring theory, NOT claimed as original mathematics.

An effect-aware optimizer checker could propagate both requirements across transformations: a rule may preserve Boolean values yet place evaluation below a boundary where the input cardinality changes from positive to zero. Our prior order and top-k obligations form further effect dimensions requiring careful provenance; not all relational operators preserve them.

### Strict scientific limitations

This is a *narrow, small finite-model source-interpreter*, not arbitrary SQL equivalence or an automatic optimizer correctness proof. Known SPARK-58429 already has an existing upstream proposal, so no novel Spark bug or duplicate PR is claimed. The historic wrong-result calibration families now have three independent source-derived interpreters (join, IN, empty aggregate), but the prior retrospective 0/3 generalized detection remains unchanged.
